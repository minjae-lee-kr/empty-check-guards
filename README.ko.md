# Empty Check Guards

[English](README.md) · [한국어](README.ko.md)

**“발견한 문제가 없음”과 “검사한 것이 없음”은 다릅니다.**

발견 사항, 검사 범위, 다음 결정을 분리하는 작은 자동화 도구입니다. 프로세스가 정상 종료하고 발견 사항이 0개여도, 필요한 범위를 검사하지 못했다면 통과로 처리하지 않습니다. 외부 의존성은 없습니다.

## 반례부터 실행하기

Node.js 22 이상이 필요합니다. 설치 과정, 인증 정보, 외부 서비스를 사용하지 않습니다.

```sh
node scripts/demo.mjs
node --test
node scripts/scenarios.mjs
```

가상의 설정 파일 검사, 오류율 표본, 작업 하트비트를 비교합니다. 시나리오 도구는 입력을 삭제·재생성하거나 예외를 승인하며 실제 CLI를 호출하고, 종료 코드와 출력, 저장된 파일 상태를 함께 확인합니다.

| 관측한 내용 | 판정 | 종료 코드 | 다음 결정 |
| --- | --- | ---: | --- |
| 충분히 검사했고 발견 사항 없음 | pass | 0 | 진행합니다. |
| 위반 발견 — 검사 범위가 부족해도 동일 | fail | 1 | 위반과 검사 누락을 함께 보고합니다. |
| 발견 사항은 없지만 근거가 부족함 | inconclusive | 2 | 검사 범위를 복구해야 합니다. |
| 판정 불가에 대한 명시적 예외 승인 | **여전히 inconclusive** | 0 | 승인자 표기, 사유, 허용한 누락을 남깁니다. |

**예외 승인은 진행 여부를 바꿉니다. 불확실성을 검증 근거로 바꾸지는 않습니다.** 위반이 발견된 실행에는 예외를 적용할 수 없습니다.

## 구현에서 볼 세 가지 판단

- **실제로 검사한 범위:** 대상을 중복 계산하지 않고, 건너뛰려면 이유를 남깁니다. 읽지 못했거나 형식이 잘못된 입력을 정상 결과로 바꾸지 않습니다.
- **마지막 유효한 판정의 보존:** pass 또는 fail에 도달했을 때만 하트비트를 갱신합니다. 예외 승인을 받은 inconclusive도 갱신하지 않습니다. 임시 파일에 쓴 뒤 교체하므로 일반적인 쓰기 실패에서 이전 기록을 보존합니다.
- **모호한 입력의 거부:** 숫자 자동 변환, 잘못된 근거, 알 수 없거나 반복된 CLI 옵션으로 정책이 조용히 약해지지 않게 합니다. JSON 결과는 종료 코드와 별개로 원래 판정을 유지합니다.

핵심은 [`CheckReport`](src/guards.js)입니다. [상세 설계](docs/design.md)에는 예제별 실패 경로, 하트비트의 의미, 파이프라인 연동 범위가 있습니다.

## 확인하지 못하는 것

검사 범위는 개수로 계산하며 반드시 포함돼야 할 대상 목록과 대조하지 않습니다. 지표 버킷의 시각이 요청한 시간 구간에 속하는지도 검사하지 않습니다. 예외 승인자와 하트비트 작성자의 신원을 인증하지 않습니다. 파일 교체는 분산 잠금이나 전원 장애 후의 내구성 보장이 아닙니다. 판정 불가 결과의 전달과 감시 작업 자체의 모니터링은 사용하는 파이프라인에서 구성해야 합니다.

예제, 서비스, 수치, 임계치는 모두 가상의 개인 작업입니다. 회사 구현이나 실서비스 성과를 재현하지 않습니다.
